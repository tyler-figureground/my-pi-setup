# Phase 6 threat model - cross-session messaging and persistent memory

Status: design-time security gate. Controls below are required implementation behavior; acceptance probes remain evidence to collect.

## Security boundary

Phase 6 provides host-bound session identity, project-scoped discovery, durable ordered mailboxes, explicit scoped memory, bounded retrieval, and managed-storage deletion. `CapabilityPolicy`, `ProjectIdentity`, `StateStore`, `ArtifactStore`, and lifecycle ownership remain host controls.

Phase 6 does **not** provide an operating-system sandbox, a separate Windows account, filesystem encryption, or a transaction spanning SQLite and Pi session JSONL. Processes run with the local user's privileges. Content provenance authenticates which admitted Session Incarnation sent a message; it does not make that content true, trusted, or authorized.

The managed deletion boundary covers canonical Memory content, revisions, citations, relationships, FTS rows, staging data, and live `memory.sqlite` sidecars. It does not promise erasure from SSD remanence, filesystem snapshots, crash dumps, retained backups, or explicit exports.

## Assets

- Process-held Session Incarnation proof, proof verifier, Lease owner, and fencing token
- Session Presence, logical session ID, Project Identity, Execution Role, cwd, name, status, capabilities, and visibility choices
- Mailbox order, envelope metadata, delivery claims, acknowledgements, idempotency receipts, transcript message IDs, and immutable body Artifacts
- Memory content, revisions, citations, scope keys, confidence, expiry, contradiction links, import staging, FTS terms, snippets, and deletion tombstones
- User and project isolation, direct-user authority, plan-mode state, child-role restrictions, and policy decisions
- Secrets in user input, model input, messages, imports, citations, logs, errors, Artifacts, SQLite files, WAL/SHM sidecars, backups, exports, transcripts, and child prompts
- Availability of Pi sessions, SQLite databases, Artifact storage, delivery pumps, lifecycle shutdown, and bounded model context

## Trust boundaries

| Boundary                                                                        | Security treatment                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Direct user command and host-issued approval                                    | Only source of direct-user authority. Bound to one operation and current host state                                                                                                                                |
| Platform composition                                                            | Trusted to read Pi session ID, resolve Project Identity, assign Execution Role, issue process proof and request IDs, and bind current workspace Lease                                                              |
| Model tool arguments                                                            | Untrusted requests. May choose bounded intent fields, never sender, raw scope key, proof, fence, role, ingress, authority, timestamp, citation identity, or policy result                                          |
| Other Pi sessions                                                               | Authenticated local provenance, untrusted content. Session names, capabilities, summaries, and bodies remain data                                                                                                  |
| Repository, transcript, message, Memory, citation, import, and Artifact content | Untrusted data that may contain prompt injection, false claims, secrets, stale facts, control characters, or authority-shaped text                                                                                 |
| `StateStore`                                                                    | Trusted coordination seam for bounded mailbox metadata, ordered events, idempotent receipts, and fenced Leases. Not suitable for forgettable Memory plaintext because transaction receipts retain written metadata |
| `ArtifactStore`                                                                 | Trusted immutable, content-addressed body seam with quotas and expiry. No per-owner targeted deletion; shared body ownership cannot be inferred from a digest                                                      |
| Dedicated `memory.sqlite`                                                       | Trusted canonical Memory repository. Scope predicates, revisions, FTS projection, deletion, and import staging must share its transaction boundary                                                                 |
| Pi transcript delivery adapter                                                  | Trusted runtime seam bridging mailbox state and Pi JSONL. Must preserve custom-message provenance and idempotency by host message ID                                                                               |
| Windows filesystem and process runtime                                          | Local-user boundary only. Same-user arbitrary file or process access is not prevented by Phase 6                                                                                                                   |

## Attacker capabilities and exclusions

In scope:

- Supply arbitrary model tool input, message text, Memory text, citations, names, capability descriptions, search queries, and import bundles
- Place prompt-injection text, fake approvals, fake system/tool messages, slash commands, role markers, authority tokens, misleading provenance, stale claims, contradictions, and secret canaries in untrusted content
- Address known sessions, retry requests, race two native Windows processes, force process crashes at claim/delivery/ack boundaries, hold SQLite readers, and create storage contention
- Fill registries, mailboxes, Artifact quota, import staging, FTS queries, context budgets, and retry queues within exposed interfaces
- Compromise repository content read by a model and induce it to request Phase 6 operations
- Corrupt or remove an Artifact, interrupt shutdown, suspend a process past Lease expiry, or restart/resume a logical Pi session

Excluded assumptions:

- Arbitrary same-user modification of platform SQLite, Artifact files, Pi JSONL, process memory, trusted extension code, or managed user configuration
- Administrator, kernel, credential-store, or physical-device compromise
- Recovery of deleted bytes from SSD wear leveling, filesystem snapshots, crash dumps, or copies the user exported or backed up separately
- Truth of a message, Memory, citation, session name, capability description, confidence score, or contradiction result
- Delivery to a Pi transcript whose supported runtime cannot provide durable idempotent acceptance

## F10 threats and required controls

| Threat                                                                                            | Required control                                                                                                                                                                                                                                                                  | Evidence / residual risk                                                                                                                                           |
| ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Sender identity spoofing through another session ID, role, project, name, timestamp, or authority | `SessionBroker` is host-bound. Composition reads Pi session ID and host role/project, generates at least 256 random proof bits, and omits identity-shaped fields from tool schemas. Sender provenance is stamped inside the broker                                                | Reject unknown sender/proof/fence/role/project/authority fields. TypeScript branding is not a security boundary                                                    |
| Persisted verifier or logical session ID is replayed as proof                                     | Plaintext proof remains process-held and absent from State Records, Artifacts, environment, transcript, model context, logs, errors, and session JSONL. Persist only a verifier digest and opaque incarnation                                                                     | Digest alone cannot mutate. Same-user process-memory compromise is excluded                                                                                        |
| Stale process heartbeats, sends, acknowledges, or closes a replacement session                    | Claim `session:<piSessionId>` Lease on attach. Renew current owner/fence in every mutating broker transaction. Rotate proof and incarnation on resume/reload/new/fork. Reject stale callbacks with `identity_lost`                                                                | Native two-process expiry, replacement, late-callback, and close probes                                                                                            |
| PID reuse or Windows process pause resurrects ownership                                           | Authority depends on proof plus monotonically increasing Lease fence, not PID or heartbeat record alone. Expiry permits replacement; resumed stale process fails its next fenced transaction                                                                                      | Long suspension can reduce availability but must not restore authority                                                                                             |
| Registry exposes unrelated project sessions or private cwd/status data                            | Visibility defaults to `none`. `same-project` compares stable `ProjectIdentity.projectId`, shared by linked worktrees. `local-user` visibility and cross-project acceptance require explicit host/user configuration. Discovery and direct-address acceptance are separate checks | Explicit local-user visibility intentionally reveals bounded Presence fields. Names and capabilities never route or authorize                                      |
| Known logical session ID bypasses project boundary                                                | Recipient acceptance policy is evaluated even when discovery is bypassed. Optional expected-incarnation guard detects replacement. Cross-project denial fails without revealing unrelated paths or content                                                                        | Probe known-ID sends across every exposure combination                                                                                                             |
| Wildcard broadcast creates unbounded or unintended fanout                                         | Send accepts 1 to 32 unique explicit recipients. Resolve all recipients before mutation and commit all envelopes or none. No wildcard, name routing, project broadcast, or implicit child set                                                                                     | One invalid recipient aborts fanout. Future delivery lanes or broadcast modes require a new versioned design                                                       |
| Timestamp races reorder messages                                                                  | Per-recipient mailbox position assigned by the committing `StateStore` event stream defines order. Host timestamp is informational. Delivery pump claims only the lowest unacknowledged position                                                                                  | Strict order permits head-of-line blocking by a poison or failing message                                                                                          |
| Two dispatchers claim or acknowledge the same message                                             | Claims use short Leases and fences. Ack proves current Session Lease and claim fence in one transaction. A stale claim cannot ack or advance cursor                                                                                                                               | Native multi-process claim/ack contention probe                                                                                                                    |
| Crash loses a message between claim, Pi delivery, and ack                                         | Internal attempts are at-least-once. Ack occurs only after durable adapter `accepted` or `already-present`. Expired claims retry. Offline mail remains queued to the logical session ID                                                                                           | No atomic SQLite/JSONL transaction exists                                                                                                                          |
| Crash after transcript append causes duplicate visible message                                    | Pi custom-message entry carries stable host message ID. Adapter uses record-only `sendMessage(..., { triggerTurn: false })`, verifies the exact live entry, fsyncs and reads back JSONL, then returns `accepted`; restart returns `already-present` before broker ack                                         | This is an idempotent sink across two stores, not a strict distributed exactly-once transaction                                                                   |
| Corrupt, expired, or permanently unsupported head blocks mailbox forever                          | Validate envelope, Artifact digest/wrapper, delivery mode, bounds, expiry, and sender incarnation before injection. Record durable `failed` or `expired` state with bounded diagnostics before strict order advances. Never silently skip or inject corrupt body                  | Deliberate strict ordering still allows bounded head-of-line delay during retry policy                                                                             |
| Retried send creates duplicates or changes content under one ID                                   | Wiring supplies host request ID. Receipt binds sender incarnation, normalized request, recipient set, and body identity. Exact replay returns original receipt; conflicting reuse fails                                                                                           | Cancellation racing commit is resolved by retrying the same request ID                                                                                             |
| Message body forges user/system provenance or approval                                            | Deliver a Pi custom message, never `sendUserMessage`. Fixed host wrapper and details carry `trust: "untrusted"` and `authority: "none"`. Do not expand commands, templates, skills, tool calls, or role markers from content                                                      | Model may still be influenced by malicious prose; policy remains enforcement boundary                                                                              |
| Message triggers a protected action indirectly                                                    | Every later action receives a fresh `CapabilityPolicy` decision from recipient host state. Message text, capability advertisement, delivery receipt, and sender role cannot satisfy direct-user approval                                                                          | Probe fake approvals against protected browser, MCP, credential, publish, and remote-write actions                                                                 |
| Secret reaches durable mailbox or transcript                                                      | Scan structural fields, known secret forms, entropy patterns, URLs, and exact canaries before Artifact creation, `StateStore` mutation, logs, errors, tool output, child prompt, or Pi delivery. Reject high-confidence credentials; persist only approved redaction              | Scanner false negatives remain possible. Acceptance uses synthetic variants through every sink                                                                     |
| Artifact dedupe mixes provenance, retention, or ownership                                         | Store one canonical wrapper per message group, including schema and group ID. Keep sender/recipient provenance in State Records. Set immutable expiry at creation. Acknowledging one recipient never deletes a shared broadcast body                                              | Failed state commit may leave an expiring orphan; bounded collection reclaims it                                                                                   |

## F11 threats and required controls

| Threat                                                                                            | Required control                                                                                                                                                                                                                                                                                               | Evidence / residual risk                                                                                                       |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Model selects another project/workspace or upgrades provenance                                    | `MemoryStore` is bound to host Execution Role, current Project Identity, optional verified Guarded Workspace Lease, ingress, session, and source entry. Requests select only `user`, `project`, or `workspace`, never raw keys, paths, owner/fence, role, confidence, or authority                             | Workspace write revalidates matching Project Identity and live owner/fence                                                     |
| FTS searches globally and filters unrelated hits afterward                                        | Apply exact allowed-scope predicate inside candidate query. Return candidate IDs only, then reload canonical rows and recheck scope, status, expiry, revision, and deletion before rendering                                                                                                                   | Stale or malicious index rows cannot become output. Probe at SQL and public-interface layers                                   |
| Cwd aliases split or merge project memory incorrectly                                             | Project scope uses canonical `ProjectIdentity`: common Git directory for main checkout and linked worktrees; canonical directory hash outside Git. Workspace scope requires manager-owned identity, not cwd prefix                                                                                             | Repository relocation can change identity. Cross-machine portability requires explicit export/import                           |
| FTS query syntax causes injection or excessive work                                               | Bind SQL values, use literal-default FTS construction, validate any future advanced syntax, and cap query bytes, terms, prefixes, NEAR distance, candidates, snippets, results, total context, and execution time                                                                                              | SQL binding alone does not make arbitrary FTS syntax safe                                                                      |
| Missing, corrupt, or rebuilding index becomes false "no memory"                                   | Lexical index is a projection. `index_unavailable` is explicit and retryable; never return empty success. Transactional body/index updates, integrity checks, canonical reload, rebuild, and deletion probes are required                                                                                      | FTS5 improves lexical recall, not semantic truth or paraphrase coverage                                                        |
| Memory or citation becomes a system/developer instruction                                         | Render bounded quoted custom data with fixed host warning, scope, kind, citation, contradiction IDs, `trust: "untrusted"`, and `authority: "none"`. Never append Memory to system/developer prompt, Lazy Rules, user messages, hooks, or policy rules                                                          | Prompt injection can bias ordinary model output; host policy blocks authority escalation and side effects                      |
| Imported content claims approval, role, scope, confidence, or capability                          | Two-phase import reads a bounded Artifact, validates versioned manifest/records, redacts again, remaps target scope from host binding, and ignores authority-shaped archive fields. Preview is digest-bound, expiring, review-only, and search-invisible. Direct-user binding commits it                       | Unknown kinds remain quarantined. Manifest digest and scope are rechecked at commit                                            |
| Secret reaches canonical row, FTS, snippet, relationship, receipt, export, backup, log, or prompt | Secret scan runs before normalization, hashing, dedupe comparison, contradiction analysis, indexing, persistence, Artifact write, diagnostics, or error construction. Store only redacted content. Receipts and tombstones remain content-free                                                                 | Reject if scanner fails or useful content becomes empty. Never echo matched secret text                                        |
| Exact or near dedupe merges unrelated project facts                                               | Dedupe key includes resolved scope and trusted kind/version. Near-dedupe candidates never cross scope/kind and use deterministic conservative thresholds. Prefer duplicate storage over false merge                                                                                                            | Dedupe cannot prove semantic equivalence. Existing citations change only through explicit revision rules                       |
| Contradictory or stale Memory silently becomes truth                                              | Create symmetric revisioned contradiction links and return both sides; never choose a winner or silently supersede. Citations and confidence remain advisory. Exclude expired records during candidate generation before background collection                                                                 | Free-text contradiction detection has false negatives and positives. Current user input and repository evidence outrank Memory |
| Concurrent edits overwrite newer Memory                                                           | Replace/promote uses `expectedRevision`; mutation and FTS replacement are atomic. Host request ID makes racing commit replayable without storing plaintext in receipt                                                                                                                                          | Stale caller must inspect and reconcile; no last-writer-wins fallback                                                          |
| Expired or abandoned workspace Memory leaks into active recall                                    | Exclude expired, review, deleted, and abandoned-workspace records in query and canonical reload. Cleanup uses bounded batches. Normal search never returns review proposals                                                                                                                                    | Explicit administrative inspection may expose authorized review/abandoned records by design                                    |
| Forget removes search row but leaves plaintext elsewhere                                          | Dedicated `memory.sqlite` transaction deletes current body, all revisions, citation excerpts, attributes, FTS/cache rows, both relationship directions, and staging/ledger references. Keep only body-free ID/time tombstone and content-free idempotency receipt                                              | Generic `StateStore` receipts and canonical Artifacts must never hold live Memory plaintext                                    |
| SQLite free pages or WAL retain forgotten text                                                    | Enable database and FTS secure-delete before writes. Require controlled WAL checkpoint/truncation before reporting managed-body deletion complete. Busy checkpoint returns retryable failure and retrieval remains suppressed                                                                                  | Byte erasure outside managed DB/sidecars is not claimed. Long readers may delay physical completion                            |
| Backup, restore, or explicit export resurrects forgotten text                                     | Do not create automatic Memory backups until retention, deletion-tombstone, and restore reconciliation policy exists. Explicit versioned exports are redacted independent copies and warn that `/forget` cannot retract them. Restore/import always passes current preview, scope, redaction, and review gates | User-retained backups, exports, snapshots, and copied databases remain outside managed deletion guarantee                      |
| Artifact forget deletes another owner's evidence                                                  | Canonical live Memory body stays in `memory.sqlite`. `ArtifactStore` is used only for explicit import/export and external citations. Forget does not delete shared external evidence or explicit exports. Any future owned evidence requires per-owner release semantics before adoption                       | Current content-addressed store has no safe targeted owner deletion                                                            |
| Automatic extraction stores hallucinations or injected text                                       | Phase 6 composes no extractor, exit summary, compaction write, ambient promotion, provider call, or automatic-generation tool. Model/automatic/import proposals, if introduced later, enter `review` and cannot appear in normal search until direct-user promotion                                            | Automatic extraction remains absent unless labeled false-memory evaluation and user-review gate pass                           |

## Shared contention, lifecycle, and denial threats

| Threat                                                                | Required control                                                                                                                                                                                                                                                                                             | Evidence / residual risk                                                                                     |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Multi-process write races corrupt mailbox or Memory                   | Use WAL, short `BEGIN IMMEDIATE` transactions, foreign keys, bounded busy timeout, schema migrations under write lock, optimistic revisions, fenced Leases, and content-bound idempotency receipts. Never fall back to unlocked JSON/Markdown or unbounded scan                                              | Busy/locked is typed retryable failure, not partial success                                                  |
| Database or Artifact path is replaced by a link/junction              | Reuse canonical/private directory checks, regular-file validation, create-new writes, digest validation, and cooperative Artifact lock. Reject symlink/reparse entries                                                                                                                                       | Windows lacks reliable `O_NOFOLLOW`; a malicious same-user process can race filesystem calls and is excluded |
| Reload/shutdown leaves stale timer, claim, SQLite handle, or callback | Parent-owned heartbeat, poll, expiry, and checkpoint work runs under `LifecycleSupervisor`. Stop new work, abort/wait bounded delivery, release only currently fenced ownership, close short-lived database handles, and reject late completions. F11 starts no child process                                | Crash leaves claims/Leases to expire. Cleanup failure remains visible                                        |
| Child session runs platform-wide pump or impersonates Parent          | Only Parent owns registry heartbeat/delivery pump. Execution Role is host-stamped. Child roles cannot orchestrate or self-assert Parent; future child results route through a Parent-owned broker with preserved provenance                                                                                  | Child read access remains subject to scope and visibility policy                                             |
| Plan mode sends work or changes durable memory                        | Discovery, message inspection, and scoped Memory search are reads. Send is `orchestration`; remember/edit/forget/import/export are writes. `CapabilityPolicy` checks plan-mode denial before hooks or message-derived suggestions                                                                            | Tool hiding is usability only; host policy remains mandatory for every call                                  |
| Queue or index work exhausts disk, CPU, context, or startup           | Enforce recipient, body, summary, transaction, pending-message, Artifact, query, candidate, import, result, snippet, context, retry, and attempt caps. Use cursor pagination, indexed queries, bounded maintenance, mailbox quota, and durable `mailbox_full` backpressure. Open nothing while flags are off | Strict ordering and bounded queues can deny service to one recipient; never silently drop or reorder         |
| Retry storm amplifies contention after restart                        | One Parent pump per logical session, fenced claim, immediate in-process wake, bounded recovery pages, jittered active polling, exponential idle/retry backoff, and maximum delivery attempts                                                                                                                 | Permanent failure becomes visible before order advances                                                      |
| Startup or integrity failure silently disables isolation              | Fail closed on schema-too-new, migration, integrity, FTS, Artifact, or identity resolution errors. Do not register partial write surfaces or return empty retrieval                                                                                                                                          | Read-only diagnostics must remain bounded and content-free                                                   |

## Residual risks

- Pi's message API returns no receipt. The adapter establishes its own flush/readback receipt using supported read-only session APIs. This supports idempotent visible transcript effects, not strict atomic exactly-once delivery across Pi JSONL and broker SQLite.
- A malicious Memory or message can influence model reasoning despite an untrusted-data wrapper. Host policy prevents authority and side-effect escalation; it cannot guarantee sound model judgment.
- Secret detection can miss novel credentials or over-redact benign high-entropy text. Exact known-secret canaries and structural scanning reduce, not eliminate, this risk.
- Lexical FTS misses paraphrases and contradiction detection is advisory. Confidence and citations help inspection but do not establish truth or freshness.
- Strict mailbox order creates bounded head-of-line blocking. Backpressure preserves data at the cost of availability.
- Explicit `local-user` registry visibility reveals bounded project/cwd/status metadata across projects. Default remains hidden or same-project.
- Artifact expiry and content addressing do not provide per-recipient erasure. Shared mailbox body retention follows immutable creation policy.
- Managed deletion cannot retract explicit exports, retained backups, snapshots, crash dumps, SSD remnants, or user copies.
- A same-user process can edit databases, transcripts, Artifacts, or race Windows filesystem checks. Phase 6 is not a same-user sandbox.
- System clock changes and long process suspension can expire Leases early or late. Fence validation preserves safety, but delivery may pause until recovery.

## Acceptance probes

### Session identity and registry

- Start two native Windows processes with one logical Pi session ID. Second attach fails while Lease is live; replacement after expiry receives new incarnation/fence; stale process cannot heartbeat, send, ack, or close replacement.
- Inject sender, role, project, name, incarnation, proof, fence, timestamp, capability, approval, and authority fields through model input. Schema rejects them or host binding ignores them. Scan StateStore, Artifacts, logs, errors, transcript, JSONL, and environment for plaintext proof.
- Resolve main checkout and linked worktree to one Project Identity. Verify unrelated Git and non-Git projects cannot discover, address, or infer each other without explicit `local-user` visibility and acceptance.
- Verify hidden, same-project, and local-user discovery/acceptance matrices separately. Route only by logical session ID, never display name.

### Mailbox delivery

- Exchange ordered messages between two real Pi processes. Verify recipient mailbox position, not sender timestamp, defines transcript order.
- Queue mail while recipient is offline. Resume with a new incarnation and deliver each message once in order.
- Crash before claim, after claim, before adapter acceptance, after durable transcript acceptance but before ack, and after ack. Preserve one transcript entry per host message ID and no message loss.
- Demonstrate durable adapter `accepted`/`already-present` behavior across restart. If runtime cannot provide it, mark exactly-once acceptance failed.
- Race two dispatchers and stale claim fences. Only current claim advances cursor. Permanent/corrupt/expired head reaches visible failed/expired state before later delivery.
- Retry identical host request ID and receive original receipt; reuse it with changed body or recipients and fail. Cancel immediately before and during commit, then resolve by idempotent retry.
- Send to 32 explicit recipients atomically; reject 33. Inject one invalid recipient and verify no envelope commits. Fill one mailbox to quota and verify `mailbox_full` without drop or reorder.
- Deliver fake approval, user message, system prompt, tool result, slash command, XML/Markdown role markers, and protected-action instruction. Transcript preserves custom untrusted provenance; policy still denies or requests direct user confirmation.
- Seed secrets in summary, body, structured fields, Artifact wrapper, stringified errors, and exact-canary variants. Verify absence from state database/WAL, Artifact store, transcript, logs, tool results, child prompts, and handoffs.

### Persistent memory

- Remember, restart, edit, and forget through both in-memory and real native Windows SQLite adapters. Race revisions and request IDs across processes; verify one atomic outcome and deterministic replay.
- Search current workspace/project/user scopes with adversarial raw scope keys, path aliases, linked worktrees, unrelated projects, abandoned workspaces, deleted records, and injected stale FTS rows. No unauthorized body, token, snippet, citation, or count reaches candidates, output, logs, or prompt.
- Exercise literal terms, identifiers, Unicode, phrases, prefixes, boolean-looking text, malformed syntax, oversized queries, expensive prefix/NEAR forms, and time limits. Unsafe syntax fails boundedly; index failure never returns empty success.
- Store fake system/developer instructions, approval text, tool calls, role markers, exfiltration requests, controls, Markdown, and XML. Retrieval remains bounded quoted custom data and cannot change plan mode, role, scope, or policy.
- Pass secret canaries through remember, edit, citation, import preview/commit, dedupe, contradiction, FTS, snippets, diagnostics, export, and errors. Byte-scan `memory.sqlite`, WAL/SHM, Artifacts, logs, and rendered context.
- Verify exact and near dedupe stay inside scope/kind. Create contradictions and confirm symmetric links, both records visible, no automatic winner, and stable results after restart. Expired entries disappear before collection.
- Forget a unique canary. Verify absence from current/history/citation/relationship/staging tables, FTS/vocabulary/snippets, search, inspect, export, rebuild, database/WAL/SHM byte scan, and restart before reporting completion. Hold a reader open and require retryable incomplete erasure until checkpoint succeeds.
- Export a redacted bundle, forget source Memory, and verify export remains with explicit warning. Re-import only through bounded digest-bound preview, current-scope remap, redaction, kind validation, contradiction/dedupe review, and direct-user commit.
- Import oversized, deeply nested, malformed, duplicate-ID, unsupported-kind, secret-bearing, scope-forging, confidence-forging, approval-bearing, and manifest-changing bundles. No active Memory or partial generation appears.
- Record lexical retrieval precision, recall, false/stale-memory rate, scope leaks, latency, and context bytes on a versioned corpus before considering semantic retrieval.

### Policy, lifecycle, and absence

- In plan mode, allow bounded discovery/message inspection/Memory search; deny send, remember, edit, forget, import, and export even with forged approval text or hook allow.
- For every child Execution Role, deny orchestration, create no registry heartbeat or delivery pump, and prevent self-asserted Parent provenance. Verify Parent-routed results preserve original role.
- Disable messaging and memory independently. Confirm no database open, migration, timer, poller, Artifact access, command/tool surface, prompt injection, provider call, model download, socket, or child process.
- Reload, resume, fork, new, shutdown, and crash during heartbeat, delivery, import, edit, forget checkpoint, and maintenance. Verify bounded close, released or expiring ownership, no stale callback mutation, and no retained Windows database handle or descendant process.
- Run native Windows contention, busy timeout, migration race, integrity failure, Artifact lock race, disk/quota exhaustion, retry storm, and 10,000-record performance fixtures. Fail closed with bounded content-free diagnostics.
- Assert automatic extraction remains absent: no exit summary, compaction write, startup generation, ambient promotion, hidden extractor hook, automatic provider call, or review-bypassing creation path. Enablement requires separate labeled evaluation and direct-user review gate.

## Failure policy

- Unknown identity, proof, fence, scope, project, workspace Lease, delivery mode, Memory kind, import format, effect, authority, or index state fails closed.
- Storage success means durable enqueue or committed Memory mutation, not recipient obedience, truth, protected-action approval, or forensic erasure.
- Acknowledgement means durable transcript visibility only.
- Forget reports completion only after managed retrieval, bodies, revisions, index material, and live WAL copies are gone. Retrieval stays suppressed while physical cleanup is pending.
- Corruption, contention, quota, cleanup, checkpoint, and lifecycle failures remain visible and bounded. No silent drop, reorder, cross-scope fallback, empty-success retrieval, or authority upgrade.
