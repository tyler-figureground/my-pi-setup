# Research: exact current `@narumitw/pi-worktree` Phase 3 trial

Audit date: 2026-08-25  
Candidate rechecked after trial: `@narumitw/pi-worktree@0.51.5`  
Decision target: [Phase 3 F02](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md#f02-guarded-worktrees)

## Recommendation

- [HIGH | Primary + native Windows verification] **Do not adopt or wrap package commands. Build Phase 3 `WorkspaceManager` behind existing platform seams. Port reviewed behavior and tests, not package files.** Exact published `/worktree` falsely reported successful removal when an ignored `node_modules` NTFS junction remained: Git deregistered the worktree but intentionally retained junction and directory. - [package removal](https://github.com/narumiruna/pi-extensions/blob/d1879fd073ff1bbe9ef6570f42974a926ccecb57/packages/pi-worktree/src/command.ts), [Git junction behavior](https://github.com/git/git/blob/c8dff95af823bd04181a583c03f3fbb954551c30/dir.c#L3443-L3527), [F02 requirements](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md#cleanup-and-recovery)
- [HIGH | Primary] **Port these ideas:** argv-only Git mutation, NUL-delimited porcelain, exact-OID previews, post-confirmation revalidation, hidden index/submodule checks, detached-HEAD durability, administrative-history risk reporting, prune dry runs, and public Pi session switching. - [source](https://github.com/narumiruna/pi-extensions/tree/d1879fd073ff1bbe9ef6570f42974a926ccecb57/packages/pi-worktree/src), [tests](https://github.com/narumiruna/pi-extensions/tree/d1879fd073ff1bbe9ef6570f42974a926ccecb57/packages/pi-worktree/test)
- [HIGH | Local architecture] **Do not port package ownership:** interactive orchestration, global settings, package-local identity, or global prune. Phase 3 needs leases, trust/profile binding, explicit dispositions, recovery, protected-main policy, and junction detachment under existing platform authorities.

| Option                        |   Decision | Reason                                                                                                                                                                                                                            |
| ----------------------------- | ---------: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Adopt pinned commands         |     Reject | [HIGH] Reproduced false success; no lease, integration, agent-workspace, or recovery API.                                                                                                                                         |
| Wrap package                  |     Reject | [HIGH] Only extension factory exported; required policy/postconditions replace destructive path. - [manifest](https://registry.npmjs.org/@narumitw%2fpi-worktree/0.51.5)                                                          |
| Copy implementation           |     Reject | [HIGH] Preserves wrong authority and creates a fork; substantial copying requires MIT notice. - [license](https://github.com/narumiruna/pi-extensions/blob/d1879fd073ff1bbe9ef6570f42974a926ccecb57/packages/pi-worktree/LICENSE) |
| Reimplement reviewed behavior | **Select** | [HIGH] Adds local state machine and Windows guarantees without losing strong checks. Independent prior art chose same approach. - [port decision](https://github.com/threadsafe-systems/pi-worktree/issues/23)                    |

### Native Windows cleanup trial

- [HIGH | Local verification] Trial stayed under system temp. Stack: Windows `10.0.26200.9168`, Git `2.55.0.windows.2` commit `c8dff95...`, Node `26.4.0`, npm `11.17.0`, Pi `0.84.3`, candidate `0.51.5`, Kit `0.58.1`. Junction targets held disposable sentinels; no repo/live dependency tree was used.
- [HIGH | Local verification] **Ordinary ignored directory:** `!! node_modules/`; Git remove returned 0, deleted directory/sentinel, and deregistered worktree.
- [HIGH | Primary + local verification] **Ignored NTFS junction:** exact package command accepted `!! node_modules/`, invoked non-force Git remove, saw no registration, and notified `Removed worktree`. Worktree directory and junction remained; shared sentinel survived. Git intentionally treats junction as mount point, does not descend, propagates “kept” as non-error, then removes administrative metadata. - [Git recursion](https://github.com/git/git/blob/c8dff95af823bd04181a583c03f3fbb954551c30/dir.c#L3443-L3527), [worktree removal](https://github.com/git/git/blob/c8dff95af823bd04181a583c03f3fbb954551c30/builtin/worktree.c#L1364-L1434)
- [HIGH | Primary + local verification] **Dirty worktree plus junction:** exact command detected `?? untracked.txt`, issued no Git remove, retained registration/path/junction, and preserved sentinel.
- [HIGH | Primary] Current Git for Windows adds defenses because native Windows directory removal can target a directory-link destination. `mingw_rmdir()` checks `lstat`; generic recursion separately keeps mount points/junctions. Package neither owns nor verifies those version-dependent safeguards. - [Git Windows code](https://github.com/git/git/blob/c8dff95af823bd04181a583c03f3fbb954551c30/compat/mingw.c#L654-L699)
- [MEDIUM | Primary issue report] Public pnpm/Windows reports document catastrophic target deletion through PowerShell/MSYS recursive removal around junctions. Package did not invoke those commands, and current Git did not delete target in this trial. Evidence still supports mandatory detach-first cleanup with no recursive fallback. - [pnpm issue #10707](https://github.com/pnpm/pnpm/issues/10707), [Microsoft Junction](https://learn.microsoft.com/en-us/sysinternals/downloads/junction)
- [HIGH | Local architecture] Success must require all postconditions: junctions detached, targets preserved, registration absent, path absent, and administrative metadata consistent. Package checks only registration absence.

## Contradictions and hidden variables

- [HIGH | Primary + local verification] README says confirmed ignored data is deleted; Git for Windows intentionally retains junctions while returning overall success and deleting metadata. Split by **ordinary ignored directory vs junction/reparse point**. - [README](https://github.com/narumiruna/pi-extensions/blob/d1879fd073ff1bbe9ef6570f42974a926ccecb57/packages/pi-worktree/README.md), [Git source](https://github.com/git/git/blob/c8dff95af823bd04181a583c03f3fbb954551c30/dir.c#L3443-L3527)
- [HIGH | Primary] Avoiding direct recursive deletion reduces immediate target risk but is not complete cleanup. Split by **no direct target deletion vs verified disposal**.
- [HIGH | Primary + local verification] Candidate is exact, but Kit floated from tested `0.58.0` to `0.58.1`. Split by **top-level identity vs dependency closure**.
- [HIGH | Primary + local verification] Release checks passed on Ubuntu while native Windows suite had 13 failures and no junction fixture. Split by **CI host vs deployment host**.
- [HIGH | Primary] Command is reasonable for human one-shot management, but F02 needs authoritative allocation and recovery. Split by **UI workflow vs durable multi-agent state machine**.
- [HIGH | Primary] High release/download activity coexists with one human package maintainer and sparse external issues. Split by **activity vs bus factor/operational evidence**.

## Validation queue
