# Research: Phase 6 persistent memory package choice

Research date: 2026-08-27 UTC

Decision target: F11 in [`docs/PI-CAPABILITY-IMPLEMENTATION-PLAN.md`](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md#f11-persistent-memory).

[HIGH | Local method] Evidence order: tracker link, Pi package directory, npm metadata and attestations, exact tarball, exact tagged source, first-party docs/issues, then web discovery.

[HIGH | Local method] `pi-memory@0.4.2` was fetched with `npm pack --ignore-scripts`, unpacked, and read in full before any execution decision. All 2,431 lines of `index.ts`, `postinstall.cjs`, manifest, license, changelog, and README were inspected. Candidate code, lifecycle scripts, qmd, LLM calls, credentials, and live memory were not executed or accessed. No local repository code, secrets, or customer data were sent externally.

## Recommendation

- [HIGH | Primary + local static verification] **Build a narrow repository-owned `MemoryStore` over built-in `node:sqlite` and SQLite FTS5. Do not adopt or wrap `pi-memory@0.4.2`.** Package supply chain is inspectable and UX is useful reference, but runtime conflicts with required project isolation, complete deletion, redaction, untrusted-context handling, explicit-only generation, provenance, freshness, contradiction handling, and multi-process safety. [tracker](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md#f11-persistent-memory) [source](https://github.com/jayzeng/pi-memory/tree/39e6b998a2279c8fad4a2c6c64e26828c1d6023e)
- [HIGH | Primary + native Windows verification] **Use FTS5 instead of building search or taking qmd as Phase 6 baseline dependency.** Native Node `v26.4.0` on Windows x64 reported SQLite `3.53.2` with `ENABLE_FTS5`; a disposable probe passed scoped search, BM25, prefix/phrase/boolean/column queries, highlights/snippets, Porter/trigram tokenizers, vocabulary, and FTS secure-delete. [Node docs](https://nodejs.org/download/release/v26.4.0/docs/api/sqlite.html) [FTS5](https://www.sqlite.org/fts5.html)
- [HIGH | Primary + local architecture] **Reuse platform ownership seams.** Keep stable project identity, authority, lifecycle, redaction, transactions, backup, integrity, and artifact ownership repository-owned. FTS5 supplies lexical indexing only. Automatic extraction stays off; explicit commands write; future vector retrieval must pass a labeled benchmark. [SQLite ADR](../adr/0002-state-store-node-sqlite.md)

### Scope, retrieval, storage, and deletion

- [HIGH | Primary] Every session reads the same default long-term file, scratchpad, and two daily logs regardless of project. Stable mode injects them without relevance query. This violates unrelated-project isolation before qmd is considered. [context](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L780-L866)
- [HIGH | Primary] `PI_MEMORY_DIR` can isolate one process if a launcher computes a directory, but path is module-global and fixed at load. It cannot represent user, stable project, and workspace scopes in one store; cwd-derived paths would split linked worktrees. [paths](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L42-L77)
- [HIGH | Primary] qmd collection name is hard-coded `pi-memory`. Results carry display path, not authoritative memory ID, scope, kind, confidence, expiry, source, or contradiction state. [setup](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L1040-L1072) [formatting](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L2279-L2338)
- [MEDIUM | Primary] Upstream includes a selective-injection eval harness, but no committed result or release threshold was found. Harness shows intent, not retrieval quality. [eval](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/test/eval-recall.ts)
- [HIGH | Primary] Storage is Markdown/JSON under one directory. Directories inherit platform permissions; package sets no POSIX mode or Windows ACL. Synchronous writes replace whole contents. [filesystem](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L42-L127)
- [HIGH | Primary] “Forget” removes active Markdown while retaining complete restorable content forever. Package removal has no uninstall hook to purge memory or qmd data. [recovery](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L712-L775) [npm lifecycle](https://docs.npmjs.com/cli/v11/using-npm/scripts/#a-note-on-a-lack-of-npm-uninstall-scripts)
- [HIGH | Primary] qmd adds document/index content, FTS tokens, and optional vectors. Package schedules update after deletion but does not await retrieval removal, invoke cleanup, verify vector removal, or erase stale pages. [qmd lifecycle](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L1172-L1189)
- [HIGH | Primary] SQLite `DELETE` alone does not guarantee byte erasure. FTS5 needs its own secure-delete; database needs `PRAGMA secure_delete=ON` or controlled `VACUUM`; WAL and backups need retention/checkpoint policy. [FTS secure-delete](https://www.sqlite.org/fts5.html#the_secure_delete_configuration_option) [VACUUM](https://www.sqlite.org/lang_vacuum.html) [WAL](https://www.sqlite.org/wal.html)

### Redaction, prompt injection, and generation

- [HIGH | Primary] No redaction exists before disk, recovery, qmd, vectors, prompt, tool output, or summary provider. Maintainer's field report also names temporal correctness, provenance, secrets, and untrusted content as gaps. [field report](https://jayzeng.com/writing/agentmemory-field-report/#what-is-still-unsolved)
- [HIGH | Primary] Memory can originate in model summaries, tool calls, user text, edited files, or compromised context. Package elevates it into system prompt without typed untrusted-data boundary, allowing memory to resemble system instructions. [prompt](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L1539-L1584)
- [HIGH | Primary] Default exit serializes conversation, keeps newest 80,000 chars, sends it to active provider, and persists output. This contradicts generation-disabled default. [generation](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L421-L480)
- [HIGH | Primary] `PI_MEMORY_EXIT_SUMMARY=0` closes only exit generation. Write tool remains model-callable and encourages learned-preference writes. Pre-compaction also re-persists scratchpad/log tails with no disable setting. [write](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L1634-L1657) [handoff](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L1587-L1631)

### Native Windows lifecycle

- [HIGH | Primary] Positive evidence: Windows home resolution covers standard environment variants; CRLF/BOM deletion is handled; qmd args use `execFile` rather than shell interpolation; published postinstall is gated away from consumer Git configuration. [paths](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L42-L58) [changelog](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/CHANGELOG.md#040--2026-07-19)
- [HIGH | Primary] Historical issues include slow qmd probing, cold semantic timeout, exit/reload blocking, exit key errors, and path traversal. Current `0.4.2` fixes or mitigates these, so they are regression inputs rather than current confirmed defects. [issues](https://github.com/jayzeng/pi-memory/issues?q=is%3Aissue)
- [MEDIUM | Primary + source inference] qmd update/embed processes have callbacks/timeouts but no retained handles, abort signals, creation identity, or tree cleanup. Shutdown clears only debounce timer. In-flight qmd may cross reload, shutdown, or extension generation. [background qmd](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L1136-L1189)
- [MEDIUM | Primary + version inference] Package bypasses qmd's Windows launcher and invokes `node <global qmd.js>`. qmd `2.8.3` changed launcher to preserve installing Node's native-addon ABI. Bypass may fail when Pi and global qmd use different Node majors. [spawn](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L876-L945) [qmd changelog](https://github.com/tobi/qmd/blob/facd35e01359e59d938bc9418e93fb9318addee3/CHANGELOG.md#283---2026-08-16)
- [HIGH | Primary] qmd `2.8.3` adds substantial Windows/concurrency fixes: Node launcher, home resolver, busy timeout, serialized schema setup, embed process lock, graceful EOF shutdown, PID identity checks, and Windows CUDA serialization. These do not repair `pi-memory` scope, file races, authority, or ownership. [qmd changelog](https://github.com/tobi/qmd/blob/facd35e01359e59d938bc9418e93fb9318addee3/CHANGELOG.md)

## Established SQLite FTS through `node:sqlite`

- [HIGH | Primary] FTS5 supports relevance ordering, BM25, phrase, prefix, NEAR, boolean and column filters; Unicode61, ASCII, Porter and trigram tokenizers; highlights/snippets; external-content/contentless layouts; vocabulary; rebuild/optimize/integrity; and secure-delete. [official docs](https://www.sqlite.org/fts5.html)
- [HIGH | Primary] `node:sqlite` exists since Node 22.5.0 and is release-candidate stability in Node `26.4.0`. It provides synchronous databases, prepared binding, busy timeout, defensive mode, authorizers, user functions, backup, serialization, and explicit close. Dynamic extension loading defaults off and is unnecessary for built-in FTS5 here. [Node docs](https://nodejs.org/download/release/v26.4.0/docs/api/sqlite.html)

| Native probe capability | Result                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| Runtime                 | [HIGH \| Local verification] Windows x64, Node `v26.4.0`, SQLite `3.53.2`, source ID dated 2026-06-03.        |
| Build flags             | [HIGH \| Local verification] `ENABLE_FTS5`, `THREADSAFE=1`, `ENABLE_SESSION`, and `ENABLE_PREUPDATE_HOOK`.    |
| Scoped search           | [HIGH \| Local verification] Parameter-bound `MATCH` plus exact project filter returned only requested scope. |
| Ranking/excerpts        | [HIGH \| Local verification] `bm25()`, `rank`, `highlight()`, and `snippet()` passed.                         |
| Query modes             | [HIGH \| Local verification] Terms, prefixes, phrases, boolean expressions, and column filters passed.        |
| Tokenizers              | [HIGH \| Local verification] Unicode61 with diacritics, Porter, and trigram created successfully.             |
| Inspection/deletion     | [HIGH \| Local verification] `fts5vocab` and FTS `secure-delete` configuration succeeded.                     |

- [HIGH | Primary] FTS5 solves lexical retrieval, not truth, source quality, scope authority, redaction, contradiction, expiry, or prompt trust. These remain `MemoryStore` duties. Vector retrieval should wait for measured lexical misses. [scope](https://www.sqlite.org/fts5.html#overview_of_fts5)
- [HIGH | Primary] SQL binding prevents SQL-value injection but not unsafe FTS syntax. User text may be invalid or expensive boolean/prefix/NEAR input. Build bounded literal-default queries and separately validate advanced mode. [syntax](https://www.sqlite.org/fts5.html#full_text_query_syntax)
- [HIGH | Primary] External-content FTS can drift if triggers/migrations fail. Require transactional content/index updates, integrity check, rebuild, and deletion fixtures. [pitfalls](https://www.sqlite.org/fts5.html#external_content_table_pitfalls)
- [HIGH | Primary + local architecture] Existing repository SQLite work already rejected JSON and third-party `better-sqlite3`, and established WAL, `BEGIN IMMEDIATE`, busy waiting, online backup, integrity, short-lived connections, and Windows cleanup. Reuse it rather than adding qmd's second database/runtime. [ADR](../adr/0002-state-store-node-sqlite.md)

## Contradictions and hidden variables

- [HIGH | Primary] **Tracker vs package default:** tracker requires generation disabled; package enables exit-summary generation. `PI_MEMORY_EXIT_SUMMARY=0` disables one path but does not enforce explicit write authority.
- [HIGH | Primary] **“Zero dependencies” vs retrieval:** Pi directory correctly reports zero declared dependencies, while usable search requires external qmd with 178 current lock entries, six install-script packages, native addons, and optional models. Split npm manifest from operation.
- [HIGH | Primary] **“Local/private” vs provider call:** file storage/qmd are local, but default exit summary sends up to 80,000 transcript chars through active provider. Split storage locality from model transport. [source](https://github.com/jayzeng/pi-memory/blob/39e6b998a2279c8fad4a2c6c64e26828c1d6023e/index.ts#L421-L480)
- [HIGH | Primary] **“Delete” vs “recoverable delete”:** recoverability is correctly advertised; Phase 6 requires complete underlying-body deletion. Different retention contracts.
- [HIGH | Primary] **“Automatic retrieval off” vs ambient injection:** prompt-dependent qmd search is off in stable mode, but global files are injected every turn. Selective retrieval differs from static context.
- [HIGH | Primary] **Windows history vs current qmd:** qmd `2.5.x` reports include launcher, lock, timeout, and cold-model failures; `2.8.3` fixes many. `pi-memory` gives unpinned instructions and bypasses current launcher, so qmd quality does not prove integration quality.
- [HIGH | Primary] **Inspectability vs correctness:** Markdown is editable, but typed provenance, temporal validity, contradiction, secret rejection, and transactional concurrency are absent. Maintainer distinguishes storage from state management. [field report](https://jayzeng.com/writing/agentmemory-field-report/)
- [MEDIUM | Primary] **Current vs minimum Node:** FTS5 was verified on Node `26.4.0`, not minimum `22.19.0`. API exists there, but exact SQLite build and secure-delete need matrix validation.
