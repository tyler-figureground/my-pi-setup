# Research: `pi-yaml-hooks` for Phase 2 declarative hooks

Audit date: 2026-08-25  
Candidate: `pi-yaml-hooks@2026.8.11`  
Decision target: Phase 2 F08 in [`docs/PI-CAPABILITY-IMPLEMENTATION-PLAN.md`](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md)

## Recommendation

- [HIGH | Primary + local static verification] **Build against the existing platform seams. Do not adopt, wrap, or port the package implementation.** Implement execution through this repo's `TriggerEngine`, `CapabilityPolicy`, `LifecycleSupervisor`, `ProjectIdentity`, and Windows process abstractions. Package explicitly registers nothing on Windows, while this repo requires native Windows behavior. Its standalone runtime also cannot enforce plan policy or provide lifecycle-owned cancellation. - [Windows guard](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/pi/register-adapter.ts), [package requirements](https://cdn.jsdelivr.net/npm/pi-yaml-hooks@2026.8.11/README.md), [Phase 2 requirements](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md#f08-declarative-hooks-core), [accepted ADR](../adr/0003-build-declarative-hook-core.md)
- [HIGH | Primary] **Use reviewed concepts, not copied implementation:** bounded YAML input, strict schema validation, provenance, deterministic ordering, canonical path checks, recursion limits, output limits, and last-known-good reload behavior. Exact commit [`34d2e6cce7a4163949f41123b76d6510e79f7758`](https://github.com/KristjanPikhof/Pi-YAML-Hooks/commit/34d2e6cce7a4163949f41123b76d6510e79f7758) remains a design reference. - [loader source](https://github.com/KristjanPikhof/Pi-YAML-Hooks/tree/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/hooks)
- [HIGH | Primary] **Do not port:** POSIX-only bash runner, permissive package schema/import surface, package-local trust store and environment bypasses, direct Pi event registry, async queue without cancellation, follow-up-prompt `tool` action, or heuristic secret logging. These conflict with existing platform seams and F08 authority requirements; adapting them would be a rewrite with inherited excess surface. - [bash executor](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/bash-executor.ts), [schema](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/hooks/schema.ts), [runtime registry](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/pi/runtime-registry.ts), [async queue](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/runtime/async-queue.ts)

### Static implementation audit

- [HIGH | Primary] Package performs no direct HTTP, socket, DNS, or fetch calls in production source. It reads configuration/trust/session files, invokes `git`, and executes configured `bash -c` actions. Configured shell actions can make arbitrary network and filesystem calls with user privileges. - [exact source tree](https://github.com/KristjanPikhof/Pi-YAML-Hooks/tree/34d2e6cce7a4163949f41123b76d6510e79f7758/src), [bash executor](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/bash-executor.ts)
- [HIGH | Primary] Bash actions inherit the complete host environment by default, including credentials. `PI_YAML_HOOKS_ENV_ALLOWLIST` is opt-in rather than secure-by-default. This conflicts with Phase 2's secret and capability-policy posture. - [environment construction](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/bash-executor.ts), [setup reference](https://cdn.jsdelivr.net/npm/pi-yaml-hooks@2026.8.11/docs/setup.md)
- [HIGH | Primary] Debug logging is disabled unless configured, uses mode `0600` where supported, refuses symlink targets where `O_NOFOLLOW` exists, rotates at 10 MiB, and heuristically redacts common token shapes. When enabled, it records commands, arguments, stdout, stderr, paths, and prompt-delivery details. Heuristic redaction cannot prove the plan's requirement that secrets remain absent from every persisted surface. - [logger](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/logger.ts), [action logging](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/runtime/actions.ts)
- [HIGH | Primary] Project hooks are trust-gated against canonical repo/worktree paths; imports outside a project anchor, global imports, and package imports are denied by default. Three environment variables can bypass those boundaries. This is useful precedent but must be replaced by platform-owned trust and `ProjectIdentity`, not duplicated. - [config resolution](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/config-paths.ts), [import containment](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/hooks/imports.ts)
- [HIGH | Primary] Loader bounds each YAML file to 1 MiB and import recursion to 32, canonicalizes paths, detects cycles, lexically sorts directory imports, deduplicates imports, validates known events/actions, records source file/index, and resolves overrides deterministically. These are useful design references; Phase 2 should implement only required surface behind platform-owned interfaces. - [YAML envelope](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/hooks/yaml-envelope.ts), [imports](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/hooks/imports.ts), [composition](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/hooks/composition.ts)
- [HIGH | Primary] Bash execution caps stdin at 256 KiB and each output stream at 1 MiB, defaults to a 60-second timeout, then sends SIGTERM and SIGKILL to a POSIX process group. Windows process-group behavior is deliberately unsupported. - [bash types](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/bash-types.ts), [executor](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/bash-executor.ts)
- [HIGH | Primary] In-process action recursion is deduplicated and capped at depth 32. Async queues cap pending work but watchdogs only warn; they do not cancel work. Runtime exposes no shutdown/drain contract, and queue/process resources are not acquired through this repo's `LifecycleSupervisor`. - [recursion guard](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/runtime/recursion-guard.ts), [async queue](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/runtime/async-queue.ts)
- [HIGH | Primary] Failures are mostly hard-coded fail-open: nonzero/timed-out bash actions do not block unless exit code 2 occurs on `tool.before.*`; prompt-hook failures continue; action handler errors are logged and swallowed. Headless `confirm` fails closed unless an override env is set. No declarative per-hook failure policy exists. - [action runtime](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/runtime/actions.ts), [host confirm](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/pi/host-adapter.ts), [documented limitations](https://cdn.jsdelivr.net/npm/pi-yaml-hooks@2026.8.11/README.md#important-limitations)
- [HIGH | Primary] Package `tool` action does not invoke a tool through host policy. It sends a follow-up prompt asking the model to invoke a named tool. This is unsuitable for a deterministic declarative action and cannot stand in for a `CapabilityPolicy` decision. - [action runtime](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/runtime/actions.ts), [limitations](https://cdn.jsdelivr.net/npm/pi-yaml-hooks@2026.8.11/README.md#important-limitations)
- [HIGH | Primary] No integration exists with this repo's plan-mode policy. A trusted hook may execute arbitrary bash before or after an otherwise read-only tool, silently creating a mutation path outside tool classification. This is a release-blocking mismatch, not a wrapper-level detail. - [package executor](https://github.com/KristjanPikhof/Pi-YAML-Hooks/blob/34d2e6cce7a4163949f41123b76d6510e79f7758/src/core/bash-executor.ts), [Phase 2 plan-mode requirements](../PI-CAPABILITY-IMPLEMENTATION-PLAN.md#enforcement)

## Contradictions and hidden variables

- [HIGH | Primary] Package appears broadly compatible because peers are `*`; maintainer docs narrow verified Pi compatibility to exact `0.74.0`, `0.79.3`, `0.80.10`, and `0.84.1`. Split by **installability vs verified runtime behavior**. Repo baseline `0.84.3` remains unverified. - [manifest](https://registry.npmjs.org/pi-yaml-hooks/2026.8.11), [matrix policy](https://cdn.jsdelivr.net/npm/pi-yaml-hooks@2026.8.11/docs/maintaining.md)
- [HIGH | Primary] Parser has a default alias-expansion limit of 100, but Phase 2 policy says aliases should be bounded or disabled and the existing parser decision chooses disabled. Split by **generic YAML usability vs executable configuration attack surface**. F08 should use `maxAliasCount: 0` plus byte/depth/node limits. - [`yaml` options](https://eemeli.org/yaml/#tojs-options), [dependency audit](./phase-2-parser-dependencies.md)
- [HIGH | Primary] Package claims timeouts and bounded queues, but async watchdogs only report and Pi confirmation has no package-owned cancellation. Split by **bash process timeout vs whole-hook lifecycle timeout**.
