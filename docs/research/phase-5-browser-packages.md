# Research: Phase 5 browser package selection

Research date: 2026-08-26 PDT / 2026-08-27 UTC

Scope: `pi-agent-browser-native`, `pi-browser-harness`, `betterwright`, and `playwright-core`. Evidence order: npm registry metadata, downloaded npm tarballs, source at registry `gitHead`, then maintainer docs/issues and downstream reports. Tarballs were downloaded and inspected without installing packages, running lifecycle scripts, launching browsers, or accessing credentials.

## Recommendation

- [HIGH | Primary] Use an in-repo adapter over exact `playwright-core@1.62.1`. It has the strongest provenance, maintenance, Windows support, lifecycle controls, cancellable actions, native AI accessibility refs, screenshots, and diagnostics while adding no install scripts, runtime dependencies, browser download, tools, or prompt context by itself. [npm metadata](https://registry.npmjs.org/playwright-core/1.62.1) [source](https://github.com/microsoft/playwright/tree/26a9e470a7b3c7822084b09fb7f13902c5f37b51)
- [HIGH | Primary] The adapter must supply the policy layer Playwright intentionally does not: host-owned profile directory, bounded outputs/artifacts, diagnostic ring buffers, explicit download/upload approvals, origin and private-network checks across redirects, `serviceWorkers: "block"`, and deterministic shutdown. Raw `Page`, `evaluate`, routing, CDP, filesystem paths, headers, and response bodies must not be model-facing. [routing API](https://github.com/microsoft/playwright/blob/26a9e470a7b3c7822084b09fb7f13902c5f37b51/packages/playwright-core/types/types.d.ts#L10205-L10255) [service-worker caveat](https://github.com/microsoft/playwright/blob/26a9e470a7b3c7822084b09fb7f13902c5f37b51/packages/playwright-core/types/types.d.ts#L11405-L11411)
- [HIGH | Primary] Do not adopt the other packages as Phase 5 default. `betterwright@1.10.2` is the closest feature fit but young, broad, fast-changing, and not securely configured by default. `pi-agent-browser-native@0.5.0` has good Pi integration but delegates execution to a separately installed native binary with an unverified postinstall download and weaker default origin containment. Current npm `pi-browser-harness@0.11.0` has known production-install and Windows defects and intentionally controls a real authenticated profile.

### `pi-agent-browser-native@0.5.0`

- [HIGH | Primary] Published package declares Node `>=22.19`, no runtime dependencies, no npm install/postinstall hook, and optional wildcard Pi/typebox peers. A source or Git install can run `prepare`, which installs missing development dependencies with scripts disabled and builds. [package manifest](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/package.json) [prepare script](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/scripts/prepare.mjs)
- [HIGH | Primary] The npm artifact contains compiled JavaScript but no TypeScript source maps or declarations. Reproducible auditing depends on the `gitHead` source rather than the tarball alone.
- [HIGH | Primary] It requires separately installed exact `agent-browser@0.34.0`; it does not bundle that engine. That package requires Node `>=24`, creating a hidden runtime-floor conflict with the wrapper's Node `>=22.19` claim. [wrapper baseline](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/README.md) [agent-browser metadata](https://registry.npmjs.org/agent-browser/0.34.0)
- [HIGH | Primary] Installing `pi-agent-browser-native` itself does not download a browser. Installing `agent-browser@0.34.0` runs a postinstall that downloads a platform-native binary from GitHub without a published checksum verification step; on Windows it also creates command shims. An explicit `agent-browser install` later downloads Chrome for Testing. This violates Phase 5's default no-download and reviewed-install expectations unless installation is separately controlled. [agent-browser postinstall](https://github.com/vercel-labs/agent-browser/blob/v0.34.0/scripts/postinstall.js) [agent-browser source](https://github.com/vercel-labs/agent-browser/tree/v0.34.0)
- [HIGH | Primary] Native Windows process support exists: PowerShell handles `.cmd` launch, and cancellation escalates through recursive `taskkill /PID /T /F`. [process implementation](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/extensions/agent-browser/lib/process.ts)
- [HIGH | Primary] Current validation is weaker than implementation support. `0.5.0` release notes waived macOS, Ubuntu, and native-Windows re-runs for an Android-only change; `0.5.2` again waived native Windows. Historical native-Windows smoke evidence exists, but not against current source/upstream baseline. [releases](https://github.com/fitchmultz/pi-agent-browser-native/releases)
- [HIGH | Primary] Managed mode maintains one live engine session per Pi session, reloads refs/state on resume, closes it on quit or idle timeout, and owns Electron temporary data where applicable. Restore state is scoped to the Pi transcript and Git checkout generation. Automatic Windows restore fails closed without a 64-character hex `AGENT_BROWSER_ENCRYPTION_KEY`. [session source](https://github.com/fitchmultz/pi-agent-browser-native/tree/f4736a99b59a4d8e86722eb69cc30c337c567805/extensions/agent-browser/lib)
- [HIGH | Primary] Profile isolation is optional passthrough, not enforced. `--profile` uses an existing profile rather than cloning it, and upstream allowed-domain mode is incompatible with profile, state, and restore options. Authenticated-profile reuse therefore cannot be combined with this package's strongest origin containment. [command reference](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/docs/COMMAND_REFERENCE.md)
- [HIGH | Primary] Agent-facing accessibility is strong: interactive `@eN` refs come from snapshots; stale or unknown refs are rejected; viewport, filter, diff, full-tree, and axe accessibility modes exist. Screenshots support viewport, full-page, element, named-path, and annotated evidence. Console, page errors, and network inspection are first-class operations. [tool contract](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/docs/TOOL_CONTRACT.md)
- [HIGH | Primary] Cancellation checks pre-aborted signals, terminates active subprocesses, then kills after a two-second grace period. Branch/session shutdown aborts and awaits owned work. One-shot script mode uses a unique restore-disabled session, limits the call count to 25, blocks profile/state/CDP/provider options, and closes in `finally`. [process implementation](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/extensions/agent-browser/lib/process.ts) [script mode](https://github.com/fitchmultz/pi-agent-browser-native/tree/f4736a99b59a4d8e86722eb69cc30c337c567805/extensions/agent-browser)
- [HIGH | Primary] Security controls include config/session ownership checks, redaction, optional allowed domains, final-URL checks, and action-policy prompts. Origin restriction is opt-in, broad purchase/account mutations remain model/prompt policy rather than hard enforcement, and the script sandbox is documented as defense-in-depth. [architecture](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/docs/ARCHITECTURE.md) [tool contract](https://github.com/fitchmultz/pi-agent-browser-native/blob/f4736a99b59a4d8e86722eb69cc30c337c567805/docs/TOOL_CONTRACT.md)
- [HIGH | Primary] Context use is relatively compact: one main tool plus optional search; snapshots cap at 6,000 characters, 80 lines, and 60 refs; generic results above 8,000 characters or 80 lines spill with a 2,500-character/40-line preview. [extension source](https://github.com/fitchmultz/pi-agent-browser-native/tree/f4736a99b59a4d8e86722eb69cc30c337c567805/extensions/agent-browser)
- [HIGH | Primary] No abandonment signal. Risk is rapid coupling churn: repository rename, session API rename, Pi package namespace migration, and source `0.5.2` already moving from `agent-browser` 0.34 to 0.35 while npm remains 0.5.0. [changelog](https://github.com/fitchmultz/pi-agent-browser-native/blob/9a5a0abbb24d53d39df298d0c528305e1506be1d/CHANGELOG.md)

### `pi-browser-harness@0.11.0`

- [HIGH | Primary] Manifest requires Node `>=22`; runtime dependency is `ws@^8.20.0`; `sharp@^0.33.0` is optional; old `@mariozechner` Pi packages and typebox are unconstrained wildcard peers. That namespace differs from this repository's `@earendil-works` Pi line and needs an explicit compatibility proof. [manifest](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/package.json#L46-L74)
- [HIGH | Primary] Package has no own install/postinstall or browser dependency. It attaches over CDP to already-running Chrome, Chromium, Brave, or Edge and can accept a remote `BU_CDP_WS`. Default optional `sharp@0.33.5` does have its own install check and platform-native optional packages, so a default dependency install is not script-free. [setup](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/setup.ts#L24-L64) [sharp metadata](https://registry.npmjs.org/sharp/0.33.5)
- [HIGH | Primary] Current npm package has a maintainer-confirmed production defect. Daemon startup needs `tsx`, but `tsx` is only a development dependency; when absent it falls back to unpinned `npx tsx`, which can attempt a registry fetch and fail. Unpublished `0.11.1` moves `tsx` to runtime dependencies and resolves its CLI. [affected source](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/daemon/spawn.ts#L81-L104) [maintainer fix](https://github.com/amankumarsingh77/pi-browser-harness/pull/23)
- [HIGH | Primary] Windows support is intentional: browser/profile discovery under `%LOCALAPPDATA%`, executable lookup, PowerShell process detection, and a Windows named pipe. npm `0.11.0` is still broken for `browser_run_script`: hard-coded slash containment rejects every Windows absolute path. The maintainer merged a fix after release, but has not published it. [Windows code](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/profile/paths.ts#L29-L69) [issue](https://github.com/amankumarsingh77/pi-browser-harness/issues/22)
- [HIGH | Primary] It offers a dedicated window and owned tabs, not a dedicated profile. It intentionally controls the user's real cookies, logins, extensions, and CDP endpoint. A global profile pin is stored under `~/.pi/agent/browser-harness.json`. Normal tab tools enforce owned targets, but all tab metadata is enumerable and arbitrary scripts receive a full client that can bypass ownership helpers. [README](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/README.md#L49-L64) [tab ownership](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/tabs.ts#L6-L44) [script surface](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/js.ts#L136-L217)
- [HIGH | Primary] Accessibility uses the full CDP AX tree, caps at 1,000 nodes by default and 5,000 maximum, and creates `[eN]` refs backed by backend node IDs and coordinates. Refs survive only while those node IDs do; replaced nodes and fresh snapshots can renumber them. [snapshot](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/snapshot.ts#L23-L39) [ref resolution](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/ref-resolve.ts#L49-L78)
- [HIGH | Primary] Screenshots support viewport/full-page PNG or JPEG and optional resizing. Tool content returns only a filesystem path and `attached:false`; pixels render to the human terminal but are not attached to the model. Screenshot and PDF temp files are outside truncation cleanup and persist until OS/user cleanup. [screenshot](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/screenshot.ts#L39-L74) [paths](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/util/paths.ts#L13-L20)
- [HIGH | Primary] Console and network buffers are useful and bounded at 500 entries per tab. Network data covers method, URL, resource type, status, timing, size, loading failure, and optional bodies, but not headers or request-body content. Exact source does not ingest `Runtime.exceptionThrown`; page exceptions depend on console/log behavior. [console buffer](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/cdp/console-buffer.ts#L38-L52) [network buffer](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/cdp/network-buffer.ts#L57-L117) [session events](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/cdp/session.ts#L116-L145)
- [HIGH | Primary] Cancellation is partial. Serialized mutex acquisition is not abortable, most handlers ignore the signal, and CDP calls use timeouts rather than aborts. `browser_run_script` races timeout/cancel but cannot stop non-cooperative async Node work. [tool wrapper](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/util/tool.ts#L131-L183) [script cancellation](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/js.ts#L189-L240)
- [HIGH | Primary] Session shutdown detaches, closes owned tabs, and removes truncation directories, but deliberately retains the detached daemon/client across sessions. Daemon idle shutdown is 30 minutes. Current npm `0.11.0` also predates a source fix that stops unbounded reconnect after failed or cancelled Chrome consent. [session shutdown](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/index.ts#L130-L142) [daemon](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/daemon/index.ts#L40-L80) [unpublished changelog](https://github.com/amankumarsingh77/pi-browser-harness/blob/6f455ed015b1b39324c45813a42b33ddb63e4bc9/CHANGELOG.md)
- [HIGH | Primary] Security is incompatible with a default trusted capability: no origin/private-network policy; arbitrary navigation and Node `fetch`; arbitrary readable upload paths and writable download directories; full Node `require` in script mode; and no application secret on the fixed local daemon socket/pipe. Maintainer documentation explicitly says script path/time limits are not a sandbox. [security warning](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/README.md#L369-L374) [navigation](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/navigate.ts#L14-L43) [HTTP helper](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/domains/network.ts#L12-L55)
- [HIGH | Primary] Context footprint is largest of the four adapter choices: all 40 tools register eagerly and a roughly 6,078-character browser prompt is injected. The prompt contains stale API names. Output limits vary partly with wildcard Pi peer defaults. [registry](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/registry.ts#L26-L70) [prompt](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/src/prompt.ts#L11-L126)
- [HIGH | Primary] Project is active, not abandoned. Scope has contracted: `0.11.0` deliberately removed deep-research orchestration while keeping browser search/read. [changelog](https://github.com/amankumarsingh77/pi-browser-harness/blob/f20fdf7fc4039ea71f3a8b56c7c508e46f1bbc51/CHANGELOG.md#L19-L24)
- [MEDIUM | Secondary] ClawBench is concrete downstream use, but its safety allowlist disables `browser_http_get` and `browser_run_script`. This supports the capability while independently confirming its dangerous surfaces. [ClawBench](https://github.com/TIGER-AI-Lab/ClawBench/blob/main/README.md)

### `betterwright@1.10.2`

- [HIGH | Primary] Requires Node `>=22.18`; pins `playwright-core@1.61.1` and `tldts@7.4.9`; optionally installs `patchright-core@1.61.1`; Anthropic and MCP SDKs are optional peers. It is already one stable Playwright release behind. [manifest](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/package.json#L102-L162)
- [HIGH | Primary] No npm install/postinstall lifecycle downloads a browser. Explicit `init`, `setup`, or `update` downloads BetterChromium `151.0.7922.108-r3`; artifacts are SHA-256 pinned and verified for macOS arm64, Linux x64, and Windows x64. No managed Windows arm64 artifact exists. [setup](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/README.md#L241-L258) [download manifest](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/src/chromium-fork.ts#L164-L199) [verification](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/src/chromium-fork-install.ts#L141-L225)
- [HIGH | Primary] Windows implementation is substantial: x64 managed binary, side-by-side manifest repair, DLL validation, named pipes, reserved-filename checks, profile locks, and PID-reuse handling. Release `1.10.0` fixed a Windows spawn failure caused by a missing manifest, so current `1.10.2` includes the fix but recent regressions remain relevant. [profile locking](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/src/profile-lock.ts#L1-L24) [changelog](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/CHANGELOG.md)
- [HIGH | Primary] Named profiles provide dedicated persistent browser identities, cookies, lock, daemon, and transcripts. Sessions within one profile share cookies and are not a security boundary. Vault, artifacts, runtime fallback, and browser cache remain shared across profiles; lock contention falls back to a signed-out ephemeral profile. [profile naming](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/src/profile-name.ts#L1-L19) [profile locks](https://github.com/BetterWright/betterwright/blob/991acfdb516ee5771dbb62e845adfd83d5336ba1/src/profile-lock.ts#L108-L146)
- [HIGH | Primary] Accessibility support is the most complete prebuilt option: Playwright AI ARIA snapshots, `aria-ref=eN`, iframe refs, diffs, interactive filtering, password redaction, and pruning. Snapshot default is 10,000 characters and hard cap 20,000. Oversized trees fail rather than silently truncate. ## Contradictions and hidden variables

- [HIGH | Primary] npm version and repository version diverge for both Pi wrappers. Decisions must target npm `pi-agent-browser-native@0.5.0` and `pi-browser-harness@0.11.0`, not fixes/features visible only on repository main.
- [HIGH | Primary] `pi-agent-browser-native` advertises Node `>=22.19`, while its required external `agent-browser@0.34.0` declares Node `>=24`. The effective floor is Node 24 unless independently proven otherwise.
- [HIGH | Primary] “No browser download” differs by phase. All four avoid an implicit browser download in their own npm install, but `agent-browser` downloads a native executable in postinstall, BetterWright downloads BetterChromium during explicit setup, and Playwright downloads only when its install CLI is explicitly invoked.
- [HIGH | Primary] “Windows support” differs from current Windows evidence. All candidates contain Windows code; `pi-browser-harness@0.11.0` has a confirmed Windows path bug, BetterWright fixed a recent Windows launch regression, and `pi-agent-browser-native` waived current native-Windows validation.
- [HIGH | Primary] “Dedicated window” is not “dedicated profile.” `pi-browser-harness` shares the user's authenticated browser. BetterWright named profiles and Playwright host-owned `userDataDir` provide identity isolation, although neither makes multiple sessions within one profile a security boundary.
- [HIGH | Primary] “Stable refs” means stable within a live document/node identity. Dynamic replacement, navigation, or a fresh snapshot can invalidate or renumber refs in every candidate. Tools must fail stale rather than guess.
- [HIGH | Primary] BetterWright documentation says private networks are blocked, but `NetworkPolicy()` allows private networks and loopback by default. Source defaults govern.
- [HIGH | Primary] `pi-browser-harness` “inline screenshots” are human-terminal rendering only. Model tool content contains a path, not image pixels.
- [HIGH | Primary] Cancellation claims often mean caller cancellation, not mutation termination. Playwright `1.62.1` propagates abort to its connection; BetterWright abandons the await while a snippet may continue; harness cancellation is handler-specific; pi-native kills its owned subprocess.
- [MEDIUM | Primary] Browser identity, executable availability, enterprise policy, antivirus, proxy, and Windows architecture remain deployment variables. Source inspection cannot prove behavior on this target machine.

## Survivorship-bias sweep

- [MEDIUM | Secondary] Searches for package names with `abandoned`, `deprecated`, `replaced`, and `migrated away` found no public project abandonment notice for any candidate.
- [HIGH | Primary] Absence of abandonment is not maturity. All three wrappers were created in 2026 and have one npm maintainer. Playwright has a multi-year, multi-maintainer history.
- [HIGH | Primary] `pi-agent-browser-native` shows rapid internal migration and upstream rebasing, but continued releases. This is compatibility churn, not abandonment.
- [HIGH | Primary] `pi-browser-harness` removed deep-research orchestration and has two important fixes stranded on unpublished `0.11.1`. This is scope reduction plus release lag, not abandonment.
- [HIGH | Primary] BetterWright changed browser backends several times within days. It is active but interface/backend stability is unproven.
- [MEDIUM | Secondary] Downstream evidence is mixed: ClawBench uses the harness while disabling its highest-risk tools; agent projects sometimes wrap or replace raw Playwright for semantics or anti-bot behavior. Neither pattern demonstrates a safe drop-in Phase 5 default.

## Don't Hand-Roll

| Problem | Do not build | Use instead | Boundary retained by Phase 5 adapter |
| --- | --- | --- | --- |
| Browser protocol and Windows process integration | [HIGH | Primary] A custom CDP client, selector engine, or browser downloader | [HIGH | Primary] Exact `playwright-core@1.62.1` with an existing user-approved browser or explicit separate install | Browser discovery policy, startup timeout, lifecycle registration |
| Agent accessibility representation | [HIGH | Primary] A custom AX-tree serializer/ref allocator | [HIGH | Primary] Playwright AI `ariaSnapshot` plus `aria-ref=` selectors | Output cap, redaction, stale-ref failure, action allowlist |
| Actionability and waiting | [HIGH | Primary] Sleep/retry heuristics and coordinate-first clicks | [HIGH | Primary] Playwright Locator auto-wait/actionability | Per-operation timeout and caller `AbortSignal` |
| Screenshots and browser diagnostics | [HIGH | Primary] Native screenshot capture or separate event transport | [HIGH | Primary] Playwright screenshot and Page/Context events | Artifact quota, redaction, bounded ring buffers, retention |
| Persistent identity | [HIGH | Primary] Copying or attaching to the user's live Chrome profile | [HIGH | Primary] `launchPersistentContext` with a host-owned dedicated `userDataDir` | Directory ownership, single-writer lock, cleanup policy |
| Network safety | [HIGH | Primary] Navigation-only URL checks | [HIGH | Primary] Playwright routing with service workers blocked, combined with the repository's capability/origin policy | DNS/IP/private/metadata validation on every redirect and transport; proxy-level enforcement if routing cannot cover WebSockets/rebinding |
