# Wrap Parcel watcher and ws for Reactive Monitors

Phase 7 wraps exact `@parcel/watcher@2.6.0` for recursive Windows filesystem hints and exact `ws@8.21.3` for bounded WebSocket protocol handling; MonitorRegistry retains canonical containment, snapshot reconciliation, origin policy, address pinning, reconnect, batching, persistence, and lifecycle authority. Raw `fs.watch` and Chokidar were rejected for normalization and fresh-directory gaps, while Node's global WebSocket lacks required payload, fragmentation, heartbeat, and force-close controls. Both packages load only when a matching monitor starts. Parcel's native DLL is exact-pinned, lifecycle-tested, and must never be force-deleted while a Pi process may hold it. TriggerEngine queueing remains repository-owned because generic queue packages do not provide causal suppression, keyed coalescing, durable fencing, or required shutdown semantics.
